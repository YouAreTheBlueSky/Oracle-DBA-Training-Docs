# 協作模式：「第 X 章簡報我改好了」

這份文件定義一套固定的來回方式。你只要說一句話，後面的步驟由我執行。

## 你說的

> 第 4 章我改好了

（章號以你的教材為準；初階版與進階課程的編號各自從 01 起算。若同時改了多章，說「第 4、5 章」即可。）

## 基準：用 git 的版本，不是我重建的版本

比對的基準是**上一個 commit 裡的簡報**（`git show HEAD~1:<路徑>`），不是我從模組重建的版本。
好處是基準一定就是你上次看到、我上次交付的那一份，不會因為模組變動而漂移。

流程因此變成：

```powershell
# 1. 先把你改好的檔案提交（快照進 git，之後怎麼重建都救得回來）
git add "deliver_beginner/05_….pptx"; git commit -m "使用者手改：第 5 章"

# 2. 用上一個 commit 當基準比對
python work/diff_pptx.py ch05 "deliver_beginner/05_….pptx" --as 5 --base-rev HEAD~1

# 3. 套用（會寫回模組並重建驗證）
python work/diff_pptx.py ch05 "deliver_beginner/05_….pptx" --as 5 --base-rev HEAD~1 --apply
```

第 1 步是關鍵：你的版本一旦進 git，就算後面出錯也能完整取回。

## 你要標粗體／底線時，可以直接打標記

在 PowerPoint 裡直接輸入：

| 你打的 | 重建後 |
|---|---|
| `**粗體**` | **粗體**（星號消失） |
| `__底線__` | <u>底線</u> |
| `***粗體＋底線***` | 兩者都有 |

比對時會忽略標記本身，所以「你打的 `**OPEN**`」與「重建後的粗體 OPEN」視為相同，不會一直被判定有差異。
用 PowerPoint 的粗體按鈕也可以，兩種方式都認得。

## 我做的七步

1. **找檔案**：比對工作區最近修改的 `.pptx`，確認是哪一份（不用你給路徑）。若有多份可疑，先問你。
2. **先備份（不做任何事之前）**：把你的檔案複製到 `work/proto/snapshot_chNN_<時間>.pptx`。
   這一步是 2026-11-18 的教訓——當時我在驗證前直接重建到同一路徑，覆蓋掉手改內容。
3. **比對**：以 `work/content/chNN.py` 重建一份基準到**暫存路徑**（絕不覆蓋你的檔），
   逐頁、逐形狀、逐段落比對文字、粗體／底線、段落結構、講者備忘。
4. **分類與處理**：

   | 差異類型 | 我的處理 |
   |---|---|
   | 純文字（句子、指令、通過條件） | 自動回寫模組，只改唯一出現的字串 |
   | 粗體、底線 | 自動轉成 `**粗體**`／`__底線__` 寫回模組 |
   | 講者備忘 | 存成該頁的 `NOTE_OVERRIDES`（依主題索引與頁型） |
   | 多／少一個段落、多／少一行 | 停手，回報「需人工對應」，提出對應方式 |
   | 字級、顏色、位置、插圖 | 無法回寫；改走 `FROZEN.txt` 或加 `style` 參數 |

5. **回寫後再驗證**：重建到暫存，與你的檔案比對必須 **0 差異**；有差異就停下報告，不寫入交付檔。
6. **才寫入交付檔**：寫入前會比對「檔案內容 vs 最後一次 commit」，若不同（代表有未提交的手改）就**拒絕覆蓋**：

   ```
   拒絕覆蓋：05_…pptx 與最後一次 commit 不同（可能有未提交的手改）。
     請先執行 work/diff_pptx.py 比對並 --apply，或加 --force 強制覆蓋。
   ```

7. **回報與存檔**：列出「你改了什麼／我改了模組哪一行／驗證結果」，commit 並 push。


## 回報長怎樣

```
你改了 3 處：
  第 04 頁程式碼 + SHOW PARAMETER SPFILE
  第 06 頁備忘 OFA 說明 368 字
  第 30 頁備忘 ASSM 說明 530 字
回寫模組：3 處成功，0 處略過
重新驗證：一致 [OK]｜體例檢查：都在上限內 [OK]
已 commit 25ac802 並 push
```

## 重建時只會動有變動的章節

`build_beginner.py` 與 `build_advanced.py` 會比較「章節模組」與「簡報檔」的修改時間：

- 模組比簡報新 → 重建該章
- 否則跳過，印出 `SKIP (up-to-date)`
- 全部都沒變 → 連索引與 README 都不重寫

需要時可強制：

```powershell
python work/build_beginner.py --only ch05   # 只重建第 5 章
python work/build_beginner.py --force       # 全量重建
```

這樣「只改一章」就不會讓 10 個檔案的時間戳全部變動。

## 你需要避免的三件事

| 避免 | 原因 |
|---|---|
| 用 Shift+Enter 手動斷行 | 軟換行不是文字，重建後會消失（自然折行不受影響） |
| 改完不存檔就說改好了 | 我讀到的是舊檔 |
| 改版面（字級、顏色、位置）卻沒說 | 重建會還原；請先講，我幫你加進 `FROZEN.txt` |

PowerPoint 開著檔案時我仍可讀取，但重建寫入會失敗；若要重建，我會提醒你先關閉。

## 若哪天沒有內容模組

若你拿一份不是由模組產生、或沒有版控的簡報來改，流程降級為「與上次 commit 比對」：我仍能列出差異與備份，但無法回寫模組，改動只能留在 PPTX。這種情況我會先說明再動手。
